# Reminder sequences and message patterns

Default cadences and message skeletons. These are practice-derived starting points, not rules: a firm's own cadence always wins.

## Contents

- Default cadence
- Compressing the cadence near a deadline
- Message skeletons: first request, reminder, final notice, text message
- Variations by request type
- Tone by industry

## Default cadence

| Step | When | Channel | Purpose |
|---|---|---|---|
| First request | Day 0 | Email | Full list, link, date, reason |
| Reminder 1 | Day 3 | Email | What is still missing |
| Reminder 2 | Day 7 | Email, plus text if the client agreed to texts | Shorter; lead with the blocking item |
| Reminder 3 | Day 12 | Email, or a phone call note for the firm | Offer help; ask what is in the way |
| Final notice | Day 18, or the last workable day before the deadline | Email | What the firm will do next and when |

Stop the sequence as soon as everything is received. If some items arrive, the next reminder thanks the client and lists only what remains.

## Compressing the cadence near a deadline

Count back from the last day the firm can still do the work (the "last workable day"), not from the legal deadline itself.

- More than 3 weeks out: use the default cadence.
- 1 to 3 weeks out: reminders every 2 to 3 days.
- Under 1 week: daily, and move the phone call note to the second step.

## Message skeletons

Fill the brackets. Keep the structure; rewrite the words to sound like the firm.

### First request

```
Subject: [Engagement]: what we need from you by [date]

Hi [first name],

To [do the work] we need the items below by [weekday, date]. [One-line reason the date matters.]

[Item 1]
[Item 2]
[Item 3]

Please upload them here: [secure upload link]

If an item doesn't apply to you or you can't find it, reply and tell me which one. We'll work it out.

[Sign-off]
```

### Reminder

```
Subject: Still needed: [the blocking item] ([n] items left)

Hi [first name],

Thanks for [what arrived, if anything]. We're still missing:

[Item]
[Item]

Upload here: [secure upload link]. We need these by [date] to [reason].

[Sign-off]
```

### Final notice

```
Subject: [Engagement]: next step on [date]

Hi [first name],

We haven't received [items]. If they aren't with us by [date], we will [consequence the firm confirmed].

If something is in the way, reply or call [number] and we'll help.

Upload here: [secure upload link]

[Sign-off]
```

### Text message

```
[Firm]: Hi [first name], we still need [1 or 2 items] by [date]. Upload: [short link]. Questions? Call [number]. Reply STOP to opt out.
```

Under 300 characters. No sensitive details. Only for clients who agreed to texts.

## Variations by request type

- **Signature outstanding:** one item, one link. Say how long signing takes if the user knows. Mention that the link expires only if it does.
- **Overdue invoice:** give the invoice number, amount, due date and payment link. Reminder 1 assumes an oversight. Mention late fees only if the user states them.
- **Questionnaire not completed:** say how long it takes and that progress is saved, if true.
- **Rejected item (wrong or unreadable document):** say what was wrong and exactly what to send instead ("all pages of the March statement, including blank ones").

## Tone by industry

- **Tax and accounting:** tie the date to the filing deadline or the firm's cut-off for filing on time.
- **Mortgage:** tie the date to the closing or lock timeline the loan officer supplies. State facts; do not predict underwriting outcomes.
- **Legal:** formal but plain. Do not characterize the matter or the effect of a deadline; use the lawyer's own wording for any consequence.
- **Agencies:** tie the date to the launch or the next milestone, and say what work is paused meanwhile.
